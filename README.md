# 百度网盘 → 夸克网盘 迁移实践

> 在 Windows 上把 1 TB 级别的百度网盘资料搬到夸克网盘，**不买 CloudDrive2 会员**。
>
> 这个仓库记的是**实测走通的路径和踩过的坑**，不是厂商文档的复述。所有"结论"后面都附了我这边量到的数字，你的环境会不一样，同一个测速脚本就在 `scripts/` 里。

## 先说结论

| 你可能以为 | 实际情况 |
|---|---|
| CloudDrive2 能直接把百度复制到夸克 | **不能**，跨云复制是 Core Pro 付费功能 |
| 买了 Pro 就秒传、几秒搞定 | **也不行**，百度→夸克不在秒传矩阵里，照样跑满带宽 |
| 夸克能在 CloudDrive2 里直接添加 | **不能**，CD2 支持的云盘里没有夸克 |
| 免费版完全没辙 | **有辙**：只要有一端是本地文件夹，或绕开 CD2 的复制任务 |

## 为什么「云端直连」这条路对百度→夸克不存在

CloudDrive2 官方文档原文（[Core features · Cross-cloud copying](https://www.clouddrive2.com/en/features.html#inter-cloud-copy)）：

> **Cross-cloud copying is a Core Pro feature.** As long as one end is a local folder — pulling files down from a cloud, or pushing local files up to one — every account can run it, free accounts included.

翻译：跨云复制是 **Pro 付费功能**；只有「一端是本地文件夹」时，免费账户才被允许。

再看官方的秒传矩阵（同一页面）：

| 源 ↓ / 目标 → | 阿里云盘 | 百度网盘 | 115 | 天翼 | 123 | OneDrive | Google | 迅雷 | 光鸭 |
|---|---|---|---|---|---|---|---|---|---|
| **百度网盘** | — | — | — | ✓ | ✓ | — | — | — | — |

两个事实：

1. **百度 → 夸克没有秒传**（夸克根本不在 CD2 的支持列表里）
2. 所以即使付了 Pro，这条链也**必须完整跑一遍下载 + 上传**，Pro 买到的只是「不落地到本地磁盘」

结论：**别为这个场景买 Pro，不值。**

## 实测数据

以下是我这边（Windows 11 / 百度 SVIP / 夸克 VIP / 家宽）量到的，2026-11 测：

| 指标 | 实测值 | 测量方式 |
|---|---|---|
| 百度网盘 → 本机 读取 | **29.81 MB/s** | 20 MB / 0.67 s |
| 本机 → 夸克（经 AList WebDAV）上传，单连接 | **2.75 MB/s** | 20 MB / 7.26 s |
| 上传，4 路顺序 | **1.98 MB/s** | 4×8 MB / 16.12 s |
| 上传，**4 路并发** | **5.64 MB/s** | 4×8 MB / 5.68 s |
| 并发加速比 | **2.84x** | 同上，`speedtest-parallel.ps1` |
| 小文件每个的固定开销 | **~2.2 s/文件** | 10 个 4 KB 文件共 22.06 s |
| 1 TB 耗时（单连接） | ~105.8 小时 | 按 2.75 MB/s |
| 1 TB 耗时（4 路并发） | **~51.7 小时** | 按 5.64 MB/s |
| 10 万个小文件的开销 | **~61 小时** | 按 2.2 s/文件 |

几点解读：

- **瓶颈在"上传到夸克"这一段，不在百度**。百度读取快了 10 倍，所以别去优化下载端。
- 2.75 MB/s ≈ 22 Mbps，看着不像带宽跑满，而像**单连接被限速**。这个猜想后来被验证了：**4 路并发直接跑到 5.64 MB/s（2.84x）**。所以并发数比任何"优化"都重要，1 TB 从 105.8 小时压到 51.7 小时。
- 小文件是隐形成本：占用时间的是每个文件的 HTTPS 往返 + 夸克建档，跟文件大小无关。**能打包就打包。**

> 复现方式：`scripts\speedtest-parallel.ps1` 会生成 8 份互不相同的 8 MB 数据（带随机标记，防止被秒传糊弄），先顺序传 4 个、再并发传 4 个，直接给出加速比。

样本树的形状（踩坑时顺手统计的，1 TB 里的一段）：

```
582 个目录 / 4139 个文件 / 354.74 GB / 最深 11 层 / 平均 87.76 MB 每文件
```

平均 87 MB/文件意味着这批资料**大部分是中等大小的文件，不是碎文件**，所以带宽是主要矛盾。

## 两条可行路线

### 路线 A：CD2 免费中转（官方支持，稳）

```
百度网盘 ──下载──> 本地文件夹 ──上传──> 夸克网盘
         (CD2 免费)          (CD2 免费)
```

- ✅ 官方明确说免费可用（一端是本地文件夹）
- ✅ 全自动排队、断点续跑，坏了重跑即可
- ❌ 占用本地磁盘，**同一时刻盘上会有两份**（CD2 缓存 + AList 上传临时）
- ❌ 需要手工分批：单批 ≤ min(缓存上限 ÷ 2, 剩余空间 ÷ 2)

### 路线 B：自建直传（不落地）

```
百度网盘 ──CD2 免费挂载──> B:\ 盘 ──HTTP 流式──> AList ──> 夸克
```

- ✅ 硬盘不落地（只有 AList 为了算哈希会暂存**单个文件**）
- ✅ 绕开 CD2 的复制任务，因此不触发 Pro 限制
- ✅ `scripts/transfer/` 是**多路并发**上传（默认 4 路），实测比单线程快 2.84x
- ✅ 端到端已验证：本地测试树 → 夸克，含中文路径、嵌套目录、空目录，断点续跑正常
- ⚠️ 源端是 CloudDrive2 网络挂载时，遇到网络抖动可能卡住读取（网络挂载没有 IO 超时）；挂载层本身的可读性我这边验证过，但**没有跑过 1 TB 全量**

## 环境准备

| 组件 | 版本（实测） | 作用 |
|---|---|---|
| Windows | 10/11 x64 | 宿主 |
| [AList](https://github.com/AlistGo/alist) | v3.66.0 | 提供夸克的 WebDAV 入口 |
| [CloudDrive2](https://www.clouddrive2.com/) | v1.1.3.3 免费版 | 把百度挂成盘符 |
| 百度网盘 | 最好有 SVIP | 下载速度 |
| 夸克网盘 | VIP | 上传速度 |

> 免费版 CD2 的额度：**2 个云盘 + 1 个挂载点**。正好够「百度 + 夸克WebDAV + 一个合并挂载」。

## 快速开始

```bat
:: 1. 装 AList（自动下载、解压、设临时目录、注册开机任务、只监听本机）
scripts\install-alist.bat

:: 2. 装好 CloudDrive2，把百度挂成 B:、把夸克 WebDAV 也加进去
::    然后确认环境还活着（会自动拉起 AList / CD2）
scripts\status.bat

:: 3. 测一下你的实际速度，顺便确认夸克可写
copy scripts\config.example.txt scripts\config.txt   &&  notepad scripts\config.txt
scripts\probe-webdav.bat
```

跑完第 3 步会得到 `scripts\probe-result.txt`，里面有**你自己线路的**读写速度和每文件开销。**先看这个再决定要不要搬**。

## 路线 A 步骤

1. **装 AList**：用 `scripts/install-alist.ps1`（会自动下载、解压、注册开机任务、设临时目录、默认只监听 `127.0.0.1`）
2. **AList 里加夸克**：存储 → 添加 → 类型 `夸克网盘` → 填 cookie → 挂载路径 `/quark`
3. **CD2 加三个东西**
   - 云盘：`百度网盘`（扫码登录）
   - 云盘：`WebDAV` → 地址 `http://127.0.0.1:5244/dav/quark`，用户密码用 AList 的
   - 本地存储：`本地文件夹` → `D:\relay`
4. **复制两段**（CD2 界面里「复制到」）
   - 第一段：百度 → `D:\relay\某批次`（免费，cloud→local）
   - 第二段：`D:\relay\某批次` → 夸克（免费，local→cloud）
5. **每批跑完清空 `D:\relay`**，再开下一批

## 路线 B 步骤

1. 装 AList、加夸克（同路线 A 的 1~2 步）
2. CD2 里只加 **百度网盘**，挂载成一个盘符（例如 `B:`）
3. `copy scripts\config.example.txt scripts\config.txt`，填好 `SOURCE_DIR`（指向 `B:\` 里的目录）
4. 跑 `scripts\probe-webdav.bat` 确认夸克可写
5. 跑 `scripts\transfer\transfer.bat`，先设 `MAX_FILES=10` 试跑
6. 用 `scripts\transfer\report.ps1` 检查目的地真的落了文件（它会递归列整棵树）
7. 确认没问题后把 `MAX_FILES` 改成 0 跑全量；**`PARALLEL` 是这里唯一值得调的参数**
8. 观察 AList 的 `temp` 目录占用，确保始终小于所在磁盘剩余空间

`config.txt` 里两个参数值得说明：

| 参数 | 默认 | 说明 |
|---|---|---|
| `PARALLEL` | 4 | 同时在传的文件数。实测 4 路 = 2.84x；线路好可以试 8 |
| `RESUME_CHECK` | 1 | 传前用 HEAD 对比远端大小，实现断点续跑。**全量首跑建议设 0**（每个文件省一次往返），续跑时再设回 1 |

## 仓库结构

```
scripts/
  config.example.txt      配置模板（复制成 config.txt 再填；config.txt 不进仓库）
  install-alist.ps1/.bat  装 AList：下载/解压/改端口和临时目录/开机自启/验证
  status.ps1/.bat         探活：AList 挂了就拉起来，CD2 没开就开，等盘符出现
  probe-webdav.ps1/.bat   写权限 + 读/写速度 + 每文件开销，输出 probe-result.txt
  speedtest-parallel.ps1/.bat  单连接 vs 4 并发上传，判断限速是"每连接"还是"整条线"
  transfer/
    transfer.ps1/.bat     WebDAV 流式上传（不落地），按大小断点续跑，失败重试
    report.ps1/.bat       列出目的地实际落了什么，输出 report-result.txt
    verify.bat            跑 pilot + 校验，两步合一
```

## 踩坑清单（都是实测撞过的）

| 现象 | 原因 | 解法 |
|---|---|---|
| 双击 `alist.exe` 没反应 / 只打印帮助 | AList 必须带子命令 | `alist.exe server --data D:\alist\data` |
| `alist admin set` 报 `dial tcp [::1]:5244 refused` | 服务没启动，属正常 | 忽略 |
| 批处理里中文报 `'udDrive2' 不是内部或外部命令` | cmd 按 GBK 解码 UTF-8，字节错位把行拆断 | `.bat` 只用 ASCII，或压成单行 |
| PowerShell 里中文路径变成 `鐧惧害缃戠洏` | PS 5.1 把无 BOM 的 UTF-8 脚本当 ANSI 读 | 脚本源码只写 ASCII；中文路径放进 **UTF-8 配置文件**再读取 |
| 脚本里 `$null.TrimEnd()` 直接抛异常 | 配置项缺失时取到 `$null` | 一律先 `([string]$cfg['KEY'])` 再处理 |
| `New-Object ByteArrayContent $bytes` 报 "argument count: 8388608" | `New-Object` 把数组当参数列表展开 | 改用 `[ByteArrayContent]::new($bytes)` |
| 从 CD2 挂载读大文件时脚本永久卡住 | 网络挂载的 `FileStream.Read` 没有超时 | 测速不要碰挂载，用内存数据 |
| CD2 挂载点里填中文目录加不上 | 挂载配置对中文支持差 | 只挂**根目录**，中文路径留给下游脚本 |
| CD2 新增云盘后 C 盘暴涨 | 默认数据目录在系统盘（服务模式下是 `systemprofile\Waytech`） | 设环境变量 `CLOUDDRIVE_HOME=D:\CloudDrive2` 后**重启** |
| 找不到 CD2 的端口 | 应用和核心端口不同 | 核心 `19798`（HTTPS `19799`），桌面应用 `29798` |
| 复制任务一秒报错，目标端零字节 | 触发了 Pro 付费墙 | 换路线 A，或走路线 B |
| 夸克 cookie 隔几小时失效 | `__puus` 约 3 小时轮转 | AList 会自动刷新回 `config.json`，别手工改 |
| 传完一个文件磁盘少了两份空间 | WebDAV PUT 无哈希，AList 需整文件落 `temp` | 按「两份」算容量 |

## 容量与速度规划

```
单批最大体积 = min( CD2 缓存上限 ÷ 2 , 目标盘剩余空间 ÷ 2 )
预计耗时(小时) = 总MB ÷ 上传速度(MB/s) ÷ 3600 × 1.3(损耗系数)
```

按**实测的 5.64 MB/s（4 路并发）** 推算：

| 数据量 | 纯带宽耗时 | 加 30% 损耗 |
|---|---|---|
| 100 GB | ~5.0 小时 | ~6.6 小时 |
| 500 GB | ~25.2 小时 | ~33 小时 |
| 1 TB | ~51.7 小时 | ~67 小时 |

> 1 TB ≈ **2.8 天不关机**。如果只用单连接（`PARALLEL=1`），这个数字会翻倍到 5.7 天。
> 先跑 `scripts\probe-webdav.ps1` 和 `scripts\speedtest-parallel.ps1` 量你自己的线路，再套上面的公式。

如果资料是**海量小文件**，除了带宽还要算「每文件开销」：每次 PUT 都有一次 HTTPS 往返 + 夸克建档。
实测 **2.2 秒/文件**，10 万个文件 ≈ 61 小时，这部分和带宽无关，**打包成大文件传输能显著省时间**。

## 尚未验证 / 已知限制

诚实标注，避免误导：

- **没跑完 1 TB 全量**。端到端验证用的是本地测试树（5 个文件 / 22.1 MB，含中文、嵌套、空目录），全量只跑过目录遍历样本。
- **源端是 CD2 网络挂载时，读文件可能卡死**。网络挂载的 `FileStream.Read` 没有超时，网络一抖就无限期阻塞——我这边就因为这个卡过一次。所以测速脚本一律用内存数据，不碰挂载。
- **CD2 挂载会自己消失**。我这边的挂载点跑着跑着就没了（CD2 进程还在，盘符不见了），需要在 CD2 界面里重新登录。跑全量期间建议时不时 `scripts\status.bat` 看一眼。
- **并发上限没试出来**。只测到 4 路 2.84x，8 路 / 16 路能不能继续涨、还是撞到夸克自己的上限，没有结论。`PARALLEL` 支持 1~16，可以自己扫。
- **长路径**：Windows 默认 `MAX_PATH=260`，这个样本树最深 11 层，中文目录名极易超过。脚本没有做 `\\?\` 前缀处理，超长路径会失败——**迁移前先检查最深那批目录**。
- **非法字符**：源端文件名里的 `? * < > | "` 之类，夸克/WebDAV 可能拒绝，脚本会记为 fail 并继续。
- **两阶段设计的内存**：扫描阶段把整个文件列表放内存（约 200 字节/文件）。几十万文件没问题，上百万就不适合了。
- **不做删除**：脚本只上传，从不删除源文件。迁移完成后源盘留多久由你自己决定。

## 安全提醒

- **别把 AList 密码、夸克 cookie、CD2 token 提交进仓库**。本仓库脚本一律从 `config.txt` 读取，且 `config.txt` 已在 `.gitignore` 中。
- AList 默认监听 `0.0.0.0:5244`（整个局域网可访问）。`install-alist.ps1` 默认改成 `127.0.0.1`；需要远程访问时显式传 `-BindAddress 0.0.0.0`。
- 夸克 cookie 等同于账号凭证，泄漏等于把网盘交出去。
- 运行产物（`*-result.txt`、`*-console.txt`、`status.txt`、`*.log`）里面带本机路径，也已在 `.gitignore` 中。
